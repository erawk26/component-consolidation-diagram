video_carousel: the remaining gap

TRANSFORMER WRITTEN, not yet run anywhere

248 components holding 489 slides, all remote_video. Consolidated by nothing until now. Added as a media_carousel source on fix/eo-video-carousel-consolidation. Its slides are copied across as remote_video with no paragraph conversion, because field_media_slides already allows that bundle.

Blocker before this runs: video_carousel has component-level heading and body fields (the H2 and intro above the carousel). media_carousel has neither. 152 of 248 components carry a heading and 111 carry a body, so running this today loses 152 headings. Slide paragraph types inside a carousel

The bundles allowed on field_media_slides are not interchangeable, and only two may ever be created by a migration. This rule was missing from the original design document and is the reason a conversion nearly destroyed listing references on 55 slides.

BundleUseLive count
media_with_captionImage slides1,261
remote_videoVideo slides. Carries field_listing_refs and field_profile_reference11
media_slideLegacy only, never emitted by a migration. Has no equivalent for listing or profile references175

Naming trap: media_carousel was labelled Video Slideshow from 2021 until it was renamed to Horizontal Media Carousel on 2026-08-10. So "Video Slideshow" in older documents means media_carousel itself, not video_carousel, and media_slide is that legacy bundle's slide type. The 175 remaining media_slide paragraphs are scheduled for migration to remote_video.

slideshow_experience stays standalone

DECIDED, locked by a unit test

Earlier versions of this page showed slideshow_experience folding into media_carousel. That is no longer the plan. It is the genuine content slide carousel and remains its own component, with 75 instances on live. MediaCarouselTransformer rejects it explicitly so a stale map row cannot replay it.
